# Conduit v0.8.6

Workspaces can live on any client in the network, not only on the hub. The
server at the centre of a network is now called the hub, and the app's two
halves are Chat and Work.

## Upgrading

- Clients paired under v0.8.5 keep their pairing. Update `conduit-node` and
  the apps along with the server: a client on v0.8.5 still connects, but the
  hub cannot browse it or mount its folders.
- Only one `conduit-node run` runs per node home. A newer run stops an older
  one, and a node whose connection is taken over by another stops itself.

## Workspaces on other clients

- New workspace in Work starts with a choice of machine: the hub, this
  computer, or any client online. A workspace on a client works as one on
  the hub does, with its own chats, files, terminals and source control.
- In the apps, This computer picks a folder with the system's own file
  picker. Conduit's explorer is for browsers and for other machines.
- A client can let the hub browse its files (Let browse in Settings →
  Devices). The hub can then list folders anywhere on it and mount one, with
  the edit and command rights the client sets for new folders. Home folders
  and whole drives are refused as too broad.
- A client that goes offline takes its workspaces with it: their sections in
  Work show when it went away, the composer says sends will wait, and files
  and terminals pick up again when it returns.
- A chat in a client's workspace offers only the profiles whose harness runs
  on that client.
- Terminals have a right-click menu with Open, Rename and Close.

## The hub and Work

- The sidebar's two halves are Chat (projects and chats) and Work
  (workspaces, terminals and harnesses, grouped by machine).
- The hub has its own page in Work: its files, with its harnesses above them.
  Every client environment has a page too, with its files, its workspaces and
  a terminal there.
- Terminal View is a right-click action on each environment's row. On the
  hub it opens the full-window terminal as before.

## Devices

- Settings → Devices takes in Servers. A server picker at the top shows each
  server's state, then a map of its network: the hub with the devices around
  it, and each device's clients.
- This device lists its clients and workspaces side by side, with switches
  for sharing, browsing and new-folder rights, and its actions underneath.
  Its name is edited here.
- A browser is grouped with the device it runs on. Download for Windows on a
  development server gives its latest local build; on a release server it
  gives the GitHub release.
- The apps find a server on the LAN by its own `.local` name, and nodes may
  pair over the private LAN.

## Interface

- Panes ease to their new widths from rest, as before v2, and start on the
  next frame.
- A chat's turn summaries load with the chat and answer in half the time.
- Buttons keep the library's own text size inside dialogs and settings.
- The Connect card's server column no longer runs past the dialog's edge.

Published for Windows x64, Android and the Linux x64 server. Installed clients
bundle their own interface and need a client update to receive these changes.

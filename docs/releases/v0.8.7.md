# Conduit v0.8.7

Files in a workspace on another device come from that device directly when
it is near. The hub answers faster and sends much less over the network.
Conduit now times every turn itself. Web search works again, and its
settings show what pi-web-access 0.44 can do.

## Upgrading

- Update `conduit-node` and the apps along with the server. A node or app
  on v0.8.6 still connects, but only an updated node reads files directly,
  tells the hub when its addresses change, or finds a hub that has moved.
- Web search moves to pi-web-access 0.44. An existing `web-search.json` is
  kept as it is. A new one no longer gets a route written into it at
  startup, so a fresh install searches in pi-web-access's own automatic order.

## Files from the nearest place

- A workspace on a device is read from that device itself when the reader
  can reach it: from this app's own machine, over the LAN, or over the
  tailnet by its Tailscale name. Otherwise it goes through the hub as before.
- A browser on the same network reads over https under the device's LAN
  name, which the hub gives it. The device must prove who it is before
  anything is read from it.
- Large files stream instead of being held in memory, up to 512 MB.

## Devices and the hub

- A device that changes address (Wi-Fi to Ethernet, a new network) tells
  the hub. A node whose hub has moved finds it again by its advertised
  identity.
- An older `conduit-node run` replaced by a newer one stays stopped. The
  Windows app's node closes with the app.
- Work lists every device and environment on the network, including those
  with no workspaces yet or that are offline.

## Faster

- A signed-in request no longer waits on a lock on the sign-in file. Every
  request is about twice as fast, and requests no longer queue behind each other.
- The model list is re-read only when its files change: model calls went
  from 20–40 ms to under 5 ms. A network refresh of the model catalogue
  serves five minutes instead of running on every app start.
- A workspace's first change check no longer waits for its file watch to
  start (4.6 s on a large repository). Its dashboard keeps chat previews
  between visits.
- File changes reach an open workspace as they happen, instead of within
  1.5 s. An idle panel asks the hub a seventh as often.
- Streamed answers and terminals are compressed on the wire, about 14 times
  smaller. So is a device's link to the hub over the tailnet.
- The interface's files are compressed once at build time, not on every
  request.
- Opening a chat by its address fetches its composer's data with the chat.
  Startup no longer loads the full model list, reads preferences three
  times, or sends every ended terminal since August.

## Chats and turns

- Conduit times each turn itself, whichever harness answered it: when it
  began, its first output, its first answer word, when it ended, roughly
  how many tokens it streamed and how fast, and each tool's time. A turn's
  time now runs to its end. Long turns no longer read as a few milliseconds.
- Times read to a tenth of a second: `352ms`, `5.3s`, `1m 02.4s`.

## The Conduit durable agent

- A codemode step lists the tools its script calls: planned from the code,
  then running and done, live and after a reload.
- A chat whose model has gone resumes on the default model, or the first
  one available, and says so.
- Large images, whether read or attached, are resized to fit the model
  instead of refused.
- Stored web search results survive a restart, so an earlier result can
  still be paged.
- Edits to `models.json`, sign-ins and the model store reach durable chats
  without a restart.

## OpenCode

- The model picker offers OpenCode's starred models, then its recent ones,
  each at the thinking level last used there, instead of all of them.
- OpenCode no longer shows as unavailable while its service has not
  started.
- A turn that fails before any answer, such as an expired sign-in, shows
  its error, live and after a reload, instead of staying on Starting.

## Web search

- pi-web-access 0.44 picks the OpenAI search model from the sign-in, so
  search through a ChatGPT account works again.
- Settings › Web search shows:
  - which provider searches, and whether the others catch its failures;
  - whether a GPT model uses its own hosted search;
  - the agent's four web tools;
  - what reading pages covers (GitHub, YouTube and video, PDFs);
  - each provider's state, with its key edited in its row.

## Interface

- A pane's document moves with the pane as it opens and closes.
- After signing out, Change server looks again for this computer's server
  and the network.
- A select keeps a value set before its choices had loaded.

Published for Windows x64, Android and the Linux x64 server. Installed clients
bundle their own interface and need a client update to receive these changes.

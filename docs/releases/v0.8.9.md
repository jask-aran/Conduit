# Conduit v0.8.9

Conduit now has a persistent agent, jbot. It keeps one home thread with
memory, routines, feeds, an inbox and an email address, and it reaches your
phone with push notifications. It asks before it acts: an approval model
judges held actions against your rules, and you answer the rest from the
notification. Chats read Narrated or Folded. Subagents branch from the turn
that started them and report back into it. Panes hold tabs of any document,
including a browser shared by you and the agents. The desktop app has its own
title bar. Settings gained Prompts, Tools, Skills, Usage, Server and Account
pages, a search, and full keyboard control.

## Upgrading

- Update the apps and `conduit-node` along with the server. Installed
  clients bundle their own interface.
- The Coding profile is retired. Its chats open on the Assistant, which now
  has jbot's reach: Executor connectors, writes asked first, and subagents.
- pi 1.4.0 (pi-ai, pi-durable, pi-coding-agent) and pi-web-access 0.46.0.
- Every chat defaults to Narrated. Folded is still in each chat's menu, and
  Settings sets one default for chats and another for jbot.
- Shortcut overrides now live on the hub in `keybindings.json`.
- On Windows, Conduit's own title bar is the default. Settings › Desktop › Title bar
  switches back to Windows' caption or turns it off.

## jbot, the persistent agent

- jbot has its own page at `/jbot`: a message stream over its home thread's
  composer, an inbox that counts what is waiting, a day strip showing the
  heartbeat's real rhythm, and a Remembered view of its memory with where
  each memory came from (prototype). Its thread opens at `/jbot/thread` as
  a tab and is never a new chat.
- Routines are one file each: a trigger, tasks, a gate and a run, with
  `RUN.md` for every run. Mode, after and before compose. An hourly gated
  heartbeat follows `HEARTBEAT.md`, there is a morning brief, and jbot
  reflects nightly in a fork of its home thread. Routines run through
  quiet hours, and seeded routines upgrade only while you haven't edited them.
- Feeds became routines. Email is one of them: the hub decodes the mail and
  turns HTML into text before jbot reads it.
- jbot has email at jbot@jask-aran.com. Mail arrives at once and shows as
  threads, with the quoted thread folded. jbot sends mail only to you, and
  to anyone else through your Gmail once you approve.
- It writes in a set house style: every message leads with what it is, and
  it never reports its own workings. You can give feedback on its messages,
  and Reflection reads that feedback. Inbox entries reach only the routines
  they are for.
- Its machine is sandboxed. Routine tasks only read, and folder reads never
  follow links.

## Approvals and push

- Push reaches your devices through UnifiedPush, browsers and Google. A
  message that was pushed carries a bell and says where it went.
- An approval can be answered from the notification: Allow once, Always (a
  saved rule) or Don't. Approvals are asynchronous: the agent asks, carries
  on and is told the answer. An approval from any chat reaches the phone.
- The approval model (pi-durable-approver) judges Executor's held actions
  against your rules, on the helper model. It follows the Rule of Two: a
  send you asked for in this turn is judged instead of coming back to you.
  It reads your intent from every channel that proves the message is yours.
- Approval cards read as fields, not JSON. Settings shows the rules as
  editable text.

## Connectors and tools

- Executor connects over MCP and is signed in from Models & accounts, from
  any client's address. Reads and read-only scripts go ahead, and writes
  ask. A card says in words what a script does and names the services it
  reached.
- Conduit is an MCP server (`conduit`). Any harness can see and arrange
  Conduit's panes and drive its browser.
- Tools are declared in a stable, append-only order and declared again only
  when they change, so the prompt cache holds.
- Skills are an index the model loads from. Conduit ships web, Python,
  Executor and routines skills. Settings › Skills turns skills on or off and
  searches and installs from skills.sh.

## Chats read Narrated or Folded

- Narrated shows the work as the trail's own lines. Each step says what it
  did, verb first. A turn has one message foot, and Done is how it ends.
  Folded keeps its orb, and the orb is Folded's alone.
- Open a chat beside itself to read it both ways at once.
- A thread is drawn as the model received it: the system prompt above the
  first message, context steps, Conduit's notes as blocks, tool changes
  named, and unseen lines marked.
- A message's time and actions show on hover. The latest exchange keeps its
  message foot, and on a phone you tap a message to see its foot.
- Transcript rhythm comes from `--flow-*` tokens. The text column is the
  composer's width.
- Find in chat reaches closed traces and steps. Up arrow recalls only your
  own messages.

## Subagents

- Subagents branch and join. A background spawn is a Started line, and its
  report jumps back to that line. Delegated says how many agents it started.
- The agents rider under the composer has Foreground and Background lists
  with daily `fg-`/`bg-` labels, a time column, Stop and Esc.
- Subagents keep their parent's tools, where before every child got the
  whole hub's. They can be named, and they have limits on concurrency,
  background runs, turns and output size.
- Runs Conduit starts are drawn as their own shape. jbot's runs outlive a
  Stop, and Stop keeps a background report that was waiting in the turn.

## Panes, tabs and the browser

- Every pane holds tabs: chats, pages, terminals and browsers, each with its
  own close. An empty pane is a New tab showing Home, and every pane has a +.
- A pane's header names its letter while there are several. The sidebar
  shows where each chat is open.
- The Browser document is a browser on the hub that you and the agents share,
  with a persistent profile. Its picture is H.264 or H.265, encoded on the
  hub, and a device's browsers are reachable from any client through the
  hub. Direct pages are on by default; a proxy mode is experimental and
  off. The Browser pane loads only when one opens.
- Closing a document eases the split instead of jumping.

## Desktop

- Conduit's title bar holds the server switcher, search, and the chats that
  are live or running. The panes start where it ends.
- The server switcher shows your profile picture or initials.

## Settings

- New pages: Prompts (each role's document and the blocks it is built from),
  Blocks, AI › Tools (each profile's tools, where they come from and their
  approval), Skills, System › Usage (a usage ledger including the hub's own
  context and approval spend), Server, and Account, with your own picture.
  Your agent knows your name.
- Settings has a search. Escape answers a field first and clears a search
  first.
- Devices shows each device's machine readout and declared harnesses.
- Models & accounts has a Helper models group that says what each model
  inherits from.

## Keyboard

- One keyboard model for every region. Modals are exclusive, Escape steps
  back one level at a time, the sidebar is one Tab stop, and every key is a
  registry command. Leader keys fill the gaps where there were no paths.
- The transcript is a list you can walk with the keyboard.
- Keyboard focus shows as a held line on the region. A keyboard tour
  teaches the model by doing.

## Prompt cache and cost

- Long cache retention. The hub keeps jbot's home thread warm between wakes,
  timed from the model's cache lifetime, and counts and shows what that
  costs.
- Diagnostics log where requests diverge and record each provider's cache
  lifetime. Prefix hashes survive a restart.

## Reliability and speed

- Logins are hardened: a per-client throttle, a cheap 429, security
  headers and scrypt 2^17.
- Scripts' sessions lapse after an hour and never count toward the device
  cap.
- Hot paths run independent reads together: startup indexes session files
  in parallel, checkpoints use bounded reads, and the file tree refreshes
  in one round trip.
- Installed clients start on their last route and race routes on wake. A
  wake keeps the route in use if it still answers. The hub hands out its
  LAN names as paths, so a moved hub stays reachable.
- Fixed: a chat list that stopped saving after one failed save, a 401
  signing out every server, startup that could load forever, requests
  that hung on the 12-hour cache hook, and stops racing a turn's start.
- Android dev APKs carry the served interface, and app updates show each
  step and can be cancelled.
- Conduit ships the full AGPL-3.0 text in `LICENSE`.

Published for Windows x64, Android and the Linux x64 server. Installed clients
bundle their own interface and need a client update to receive these changes.

# Conduit v0.7.3

A warm agent is kept five times longer, and the release process no longer
publishes a commit whose tests failed.

## Runtime

- An idle agent process is kept for five minutes rather than two. The wait this
  removes is an agent starting from cold, and two minutes was short enough that
  it was paid again inside the same sitting: a pause to read what came back was
  longer than the window keeping the process alive.
- A server that has already saved a value keeps it. The setting stays
  adjustable in Settings → System → Runtime, between thirty seconds and an
  hour.

## Desktop and Android

- The connection to the active server is opened while the page is still
  loading, so the first request does not pay a connect and a TLS handshake in
  front of an empty window. Offered only to the installed clients, whose page
  comes from the shell's own origin rather than from the server; a browser was
  served by the origin it is about to call and is already connected to it.

## Releasing

- The changelog for a tag is no longer capped at forty lines. The check exists
  to catch a file that ran away, not to set a word budget for a release that
  changed several things.
- `CONTRIBUTING.md` now requires the suite to pass locally before a commit is
  tagged. A tag is what turns a failing test into something other people
  install.

## Fixes

- Two server test files picked a port by binding zero, closing it and handing
  the number to a child process. Test files run at the same time, so both could
  be given the same number and one file's requests were answered by a server it
  never started. The kernel picks the port now and the server reports the one
  it got. The failure appeared only on a machine with a built client, which is
  why CI never saw it.

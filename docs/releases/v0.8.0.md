# Conduit v0.8.0

Server identity, secure native connections, and clearer server management.
These changes cover everything shipped since v0.7.9.

## Servers and connections

- Windows and Android clients verify direct TLS connections against the
  server identity. HTTP and TLS share the server port. A failed verified TLS
  connection does not fall back to cleartext HTTP.
- Pairing QR codes carry the server identity and available routes. Installed
  clients redeem the one-time sign-in code over a verified connection.
- Servers merge only when their identities match, rather than because they
  share an address. LAN discovery keeps each server's available routes.
- Route probes run concurrently. Clients remove routes the server no longer
  offers and mark routes that do not answer.
- Rename a server from a connected client or the CLI. Its name follows the
  server identity across clients and LAN discovery.
- The server switcher groups routes in a submenu and shows measured latency.
  Servers settings groups each server's routes, version, uptime and connected
  clients, with switching and removal actions for other servers.

## Updates and server lifecycle

- Connected browsers prepare the new interface before a restart. The server
  waits for their readiness rather than using a fixed delay; installed clients
  do not hold up this browser preparation.
- Android downloads newer release APKs inside the app and shows an Install
  action when ready. Background downloads require an unmetered connection;
  Android still asks for permission and confirms installation.
- The CLI lists each connected client, its build and connection age.
- Setup preserves the password and saved access choices, uses the identity's
  current name, and validates the port. A fresh setup defaults to loopback.
- Reconfiguring a running server waits for active answers on its previous port
  before restarting, with the existing ten-minute limit.
- Completed CLI questions and progress steps appear once. The final summary
  separates local server health from configured, unverified remote access.
- Fixes installer startup when Node is missing. Suitable installed Node is
  reused; otherwise Conduit can install a private runtime.

## Interface and installed clients

- Phone overlays and full-screen surfaces stay inside the status and
  navigation bars. Dashboard composers use the chat composer's dock.
- Fixes phone menu dismissal, submenu focus and frosted backgrounds.
- Pane swaps reveal the new pane beneath the fading old frame, avoiding a
  background flash during the transition.
- Windows remembers window placement and keyboard zoom across restarts.
- Uses the shared C mark for app icons. Development builds use inverted
  artwork; Windows keeps caption artwork without caption text.
- Speeds up Windows development builds and warms release caches on main.

## Documentation

- Combines installation, recovery, client builds, server switching and release
  constraints in `docs/DEPLOYMENT.md`. Testing guidance is `docs/TESTING.md`;
  active implementation plans are under `docs/plans/`.

## Known limitation

Chat search can show the wrong day heading immediately after a daylight-saving
clock change. This existing issue also affects v0.7.9.

Published for Windows x64, Android and the Linux x64 server. Installed clients
bundle their own interface and need a client update to receive these changes.

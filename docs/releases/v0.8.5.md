# Conduit v0.8.5

Conduit's own agent moves to the Conduit durable agent, and the server can
work on your other devices: their folders, terminals and checkpoints. These
changes cover everything shipped since v0.8.0. v0.9.0 follows once this has
run in daily use.

## Upgrading

- Conduit's own chats run on the Conduit durable agent. On first start, each
  chat still on classic Pi is converted once: its current branch becomes a
  durable conversation, and the chat keeps its title, profile and place.
  Classic Pi is removed, so the conversion does not run backwards; keep a
  copy of the data folder if you may return to v0.8.0.
- Chats of the old "Conduit runtime" profile become Assistant chats.
- The server needs Linux (WSL counts) or macOS with tmux 3.3 or newer, as
  before. Windows runs the server inside WSL.

## Conduit durable agent

- Assistant and Conduit's other first-party profiles run on the Conduit
  durable agent. Chats keep working through server restarts and dropped
  connections; a turn that was running resumes where it stopped.
- Editing an earlier message forks the chat in place, and the history tree
  shows each fork.
- `/skill:` commands run a skill, and the model picker offers the models the
  profile allows.
- A chat can move to another workspace from its menu or the dashboard; its
  history moves with it.

## Devices

- Pair a computer with the server from Settings → Devices, then run
  `conduit-node` on it. Each folder you share says what the server may do
  there: read, write, or run commands. Files that look like secrets (`.env`,
  keys, `.ssh/`) are kept back unless you allow them.
- A shared folder can become a workspace. Its chats, files, source control,
  checkpoints and terminals work as they do on the server, run on that
  device. File changes made on the device appear as they happen.
- A device's terminals keep running when the server restarts or the device
  disconnects. On Linux and macOS they also survive the device's
  `conduit-node` restarting or updating.
- A device that shares any folder with commands offers a terminal in its home
  folder, from Settings → Devices.
- One device can hold several environments, such as Windows and a WSL
  distro. Each is its own place with its own folders, shell and tools. The
  Windows app can carry its WSL distro on its own connection
  (`conduit-node relay add`), so WSL needs no pairing route of its own.
- The Windows app can serve its computer as a device: turn on Serve in the
  app, then share folders.
- A device that goes offline shows as offline: work waiting on it says so and
  continues when it returns, or you can carry on without it.

## Interface

- One Interface size in Appearance scales the whole app, with separate sizes
  for each region. Desktop text and spacing are slightly larger by default.
- Menus, settings, dialogs, notifications, the sidebar, chat search, the
  command palettes and the leader share one consistent look and spacing.
- Menus keep a gap from their control, stay inside the window, scroll when
  long and open submenus from their row. Menus rise in and fade out.
- The server menu groups its entries under titles. Downloads move into it, and
  the server name shows its connection state at the end of its line.
- The chat menu gathers Details, Context and Delete chat. Context shows the
  session's usage as totals, a legend and tiles, followed by the account plan.
- Choose the transcript font (Paper Mono or Geist) and the terminal font in
  Appearance. Section labels use one consistent style throughout.
- Settings dropdowns open the app's own menu rather than the system picker.
  Tapping outside a menu in Settings closes only that menu.
- Connect pairs a device or adds a server in one card. Adding a server looks
  it up as you type, then signs in.
- Folders slide open and shut, and focus rings no longer appear on controls.

## Transcript and sending

- A sent message appears at once. The transcript glides to it and the turn
  header fades in from the moment of sending.
- The view eases to the bottom when an answer ends rather than jumping.
- Code blocks highlight only new lines while streaming and no longer jump when
  the fence closes. Fade is the only streaming reveal; the typewriter options
  are gone.
- Streaming answers and thinking turns use noticeably less CPU, and the
  sidebar scrolls as smoothly as the transcript.
- A turn stopped or failed before showing anything still has a live header.
  Stop appears on the approval card.
- One event stream serves every tab in a browser instead of one per tab.
- A reconnecting client keeps older history, and a loaded transcript no longer
  replays the log when it attaches.
- Chats open sooner from their address, and return from the background
  reconnects at once.

## Phone

- The chat header names the chat in a pill that opens its menu, with controls
  in two frosted pills. The status line moves out of the header.
- The sidebar header holds the wordmark and close button in frosted pills,
  with the server as the first line of the list.
- Side panels open by swiping only from the screen edge.
- Toasts drop in from the top of the screen. Drawers dim the page behind them.
- Taps give haptic feedback and leave no highlight behind.
- Overlays end at the keyboard, as the composer does.
- The Android app opens on a single dark launch screen.

## Voice

- A voice-first phone composer: the mic grows into a glowing orb with a
  waveform beside it, and live captions appear over the transcript.
- Desktop dictation matches the phone, with the voice track over the composer.
- Start a new dictation while the last one is still finishing. Dictation
  failures appear as toasts, and the app explains when the mic is blocked on
  plain http.
- The voice composer keeps an edit row, camera button, Stop and send, and a
  full undo history.

## Workspace and terminal

- Swapping panes keeps focus, scroll position and a moved chat's loading state.
- The terminal keeps application mouse handling, copies selections to the
  client clipboard and supports native paste. Its shortcuts move into a menu.

## Updates, sign-in and the server

- A finished Claude Code, fx or OpenCode turn no longer counts toward the
  limit of two concurrent generations, which could block new turns with "Too
  many concurrent generations".
- Restarting from Update ready applies the update even with an unsent draft.
- Background update checks no longer show a spinner; manual checks give up
  instead of spinning forever.
- Every client says Conduit updated after a new build arrives.
- Approvals and questions can be answered from anywhere and time out in
  headless runs. Headless agent runs drive a chat over HTTP with no page open.
- Stale OAuth attempts no longer block browser sign-in.
- The installer and daemon handle PATH correctly.
- LAN browsers get a trusted HTTPS certificate on the same port, with plain
  http redirected.

## Development

- The interface is built from one in-app component library with a browsable
  gallery, replacing Tailwind and the shadcn theme.

Published for Windows x64, Android and the Linux x64 server. Installed clients
bundle their own interface and need a client update to receive these changes.

# Conduit v0.8.11

jbot becomes one place on every device: its chat is laid out as a thread,
each turn one line that says what it did in your terms ("jbot checked Gmail
and searched the web"), and its background work is one log of units, routines
and runs, each saying what it is doing now. Email is the heartbeat's first
task, read into Markdown files, and the context inbox is files in jbot's
folder. Every thread is Narrated, the v2 library carries the phone's
behaviour and draws every transcript, and the app stays usable when it can't
reach the hub.

## Upgrading

- Update the Android app along with the server: the status bar scrim, the
  safe area and notification changes are native. The phone composer is now
  native while typing by default; choose the web one in Settings ›
  Interface › Composer.
- Installed clients take their interface from the server they talk to; a
  reopen comes back to the page as it was left.
- Web tools load again: earlier runtimes started without `web_search`, and
  a hub whose web tools fail to load now says so in Needs you and
  `/healthz`.
- jbot's name is yours to choose in Settings; the app says it everywhere
  you read it.

## jbot

- jbot on a desktop is a dock tool (Ctrl+J from anywhere), with Chat, Now,
  Routines, Memory and Threads in its header; on a phone it opens from a
  frost disc in the drawer's head. Its panel is a Ledge above the composer
  on a desktop and a Tray on a phone, and Needs you is always in sight.
- The jbot chat is a thread: the chat's scroller, floating composer and
  Scroll to latest. A turn is one line, "jbot is checking Gmail" while it
  works and "jbot checked Gmail · 12.4s" once done, that opens the home
  thread. A run is a line of its own; a background agent jbot sends is a row
  under the reply that sent it until it reports.
- The turn digest names each step as an act on an object from what the
  trace already holds; threads' live status and agents' activity use it too.
- Working on, Recent and the jbot chat's run rows read one work log. A
  routine says what it is doing: Collecting emails, then what its run is
  doing, then Filing the report or Reporting to jbot, Compacting the home
  thread, and how it ended. Agents roll up into their unit. The hub pushes
  each change, so nothing polls. Routine files can name each block
  (`working`, `label`).
- A routine's play button and Run a task run whatever is left of the day's
  budget; the clock, events and webhooks still stop at it.
- Email is the heartbeat's first task, through one mail pipeline into
  Markdown files, whole emails up to 2 MB and 6 MB a firing. jbot's mail is a
  mailbox any routine reads; held mail wakes the Held mail routine (routines
  can be triggered by events).
- The context inbox is files in jbot's folder, opened in the file viewer;
  inbox lists show their latest five, the rest behind Show all.
- Routines, watches and webhooks can keep their runs out of the message log
  (`log: false`). A test report beside Run a task watches a report's turn
  end to end.
- Work the runtime parked after too many restarts shows under Needs you with
  Retry. A connector is a problem only once it has been down a minute.
- Notifications are plain text, say which hub sent them, and on Android show
  jbot's mark on Conduit's black.

## Threads and the transcript

- Every thread is Narrated: a turn header sums each turn and opens to its
  steps, runs are drawn as steps or a line (Appearance › Reasoning & tool
  use), and each heading of a reasoning summary is its own step.
- A context step opens to its text and names what a request took away.
- One fast transcript and one follow for every chat: what grows at the foot
  is followed before the frame paints, so rewrapping no longer flashes.
  Provisional rows fade only to make way, never between their own states.
- Chats made elsewhere (Float, another device) show up without reopening
  the app.

## Phone

- The drawer shuts onto a page already whole, reads its chats ahead, and a
  sidebar caught moving is held where it is; the edge swipe works in the jbot
  chat too.
- Dialogs sit above the keyboard; a menu tap no longer clicks what was under
  it.
- The status bar has the system's see-through scrim, as the navigation bar
  does.

## Desktop

- Zoom is the Interface size: Ctrl+wheel, a pinch, Ctrl+= / Ctrl+- / Ctrl+0.
- The title bar shows an update's progress with Cancel, and Up to date once.
  The hub pushes the updates it offers; clients download in the background.
- Only the Terminal maximises in the dock.

## Everywhere

- Offline: requests keep looking for the hub, changes wait to save, sends
  wait in an outbox, and chats open from the device.
- Settings › Appearance › Animation speed slows every animation (2×, 4×,
  10×) on one device to inspect it.
- The frame is three shades darker.
- A restart takes seconds again.
- Local voice is one runtime, transcribe.cpp, with Moonshine Streaming Tiny
  by default.
- Dependencies to their latest: Vite 8, Express 5, Capacitor 8.6, Tauri
  2.12, KaTeX 0.18.

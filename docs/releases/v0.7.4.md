# Conduit v0.7.4

A phone's keyboard now carries the composer and the transcript with it, a
server is one server with several routes rather than one server per address,
and both clients can find a server on the network in front of them.

## The keyboard on a phone

The keyboard used to resize the window and leave the transcript to catch up.
It overlays the page now, and the page follows it.

- The shell reads the keyboard's position from Android's inset animation and
  hands the page the whole travel at once -- its two ends, its duration and its
  own interpolator, sampled -- so the composer is drawn on every frame the
  display renders rather than on the handful a bridge can deliver. Moving the
  window in one step, at the end, was the composer arriving somewhere the
  keyboard had not reached yet.
- `@capacitor/keyboard` is gone. It registered an animation callback on the
  root view that stopped dispatch to everything beneath it, so no frame of a
  keyboard travel ever reached this code. Reporting the keyboard's height is
  this shell's own job now.
- The navigation bar's room is given up as the keyboard takes it, on the same
  curve, instead of being switched off the moment the insets change. That
  switch was a composer that jumped a navigation bar up the screen before the
  keyboard had begun to move.
- The transcript holds the line somebody was reading, against the window
  shortening and against its own content changing height as the composer it
  reserves room for grows and shrinks. Both happen on every travel, and
  correcting for one without the other lost the position a little at a time.
- A thread already at its end stays at its end when the keyboard opens.

## Servers on your network

- A server announces itself over mDNS, and both installed clients can browse
  for one. The add-server flow offers what it found before asking anybody to
  type an address, and says plainly when it found nothing.
- A server is one server with several routes. The same machine reached over
  Tailscale, over the LAN and over a tunnel used to appear as three, each with
  its own history and its own sign-in.
- A client probes its routes, takes the nearest one that answers and holds it,
  and can move a live connection to another route without dropping the sockets
  on it.
- An address has to prove it is the server the client already trusts before a
  token is sent to it, and a server learns its identity only over a connection
  that authenticated. The console helper that moved a token without that proof
  has been removed.

## Updates

- An update waits for a moment when it will not interrupt anything: a reload
  no longer arrives in the middle of an attachment or a send.
- The update is shown while it happens rather than mentioned once, and the
  reload at the end says that it was the update.

## Drafts

- A composer draft is kept where a reload cannot take it, and is restored even
  when it arrives after the chat has opened.
- Which draft wins is decided by which was saved last, not by whose clock is
  right. Both copies are dropped when the chat goes.

## Settings and the sidebar

- Settings is laid out for a phone and reads as rows rather than as a column of
  stacks, on one type scale.
- A sidebar folder grows and closes instead of appearing and vanishing, and
  only the folder that was toggled moves.
- On a touch list the scrollbar is drawn over the rows rather than beside them,
  and sidebar rows are a thumb's worth of height.

## Development clients

- The Windows development client builds into a directory of its own, so a
  running development build no longer blocks a release build from linking.
- The Android development APK installs beside the released app rather than over
  it.

## Fixes

- The Android discovery call is resolved on the thread Capacitor expects.
- Discovery publishes only the addresses its advertisement claims to publish.
- The Android updater's plugin is registered, so the shell can ask for one.

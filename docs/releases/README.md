# Release notes

Add one short Markdown file for each tagged release. The filename must match
the tag, for example `v0.3.2.md` for tag `v0.3.2`.

Keep the note to 40 lines or fewer. A short list is enough:

```markdown
# v0.3.2

- Added ...
- Fixed ...
- Deployment note: ...
```

The tag workflow checks the file before publishing the container and uses it
as the GitHub release body.
